= Module 10: Enable a Cloud IDE for developers
:source-highlighter: rouge
:toc: macro
:toclevels: 1

Parasol's developers can now utilize self-service templates to provision new application environments.  Let us take this to another level and enable developers to provision full development environments.  Imagine a world where the developers can; maintain legacy applications, add new features to growing applications, and create greenfield applications, all without having to fight with tools, dependencies, configuration, and resource constraints on their local workstations.

We will now make that happen with OpenShift Dev Spaces.

== Learning objectives

By the end of this module, you will be able to:

* Create an instance of OpenShift Dev Spaces using the CheCluster custom resource
* Launch a workspace from a git repository
* Add guardrails to Dev Spaces to set limits for CPU, Memory, and Storage use
* Create centrally managed configurations for AI harnesses

=== About Kustomize

This workshop uses link:https://kustomize.io[Kustomize,window=kustomize_docs] https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/#bases-and-overlays[overlays,window=k8s_docs] to manage the layers of configuration that construct and enhance your internal developer portal. Argo CD supports both Kustomize and link:https://helm.sh[Helm,window=helm_docs] for rendering Kubernetes manifests, allowing us to use a set of base manifests to which we apply overrides per environment or per workshop module. We chose this approach to illustrate progressive enhancement of an OpenShift Dev Spaces deployment.

https://kustomize.io/[Kustomize,window=kustomize_docs] uses the declarations in the _kustomization.yaml_ file to "render" your configuration files. 

Preview the Kustomize output in the terminal using the following commands:

[source,bash,role="execute",subs="attributes+"]
----
git clone https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/ocp-pe-wkshp-dev-spaces-config
oc kustomize ocp-pe-wkshp-dev-spaces-config/base
----

The rendered CheCluster could be applied to OpenShift using `oc apply -k`, but in your case Argo CD will take care of that.

== Exercise 2: Deploy an instance of OpenShift Dev Spaces

. In the **Terminal** tab, create the Argo CD Application:
+
[source,bash,role="execute",subs="attributes+"]
----
cat <<'EOF' | oc apply -f -
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: openshift-dev-spaces
  namespace: openshift-gitops
spec:
  project: pe-workshop
  source:
    repoURL: https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/ocp-pe-wkshp-dev-spaces-config.git
    targetRevision: main
    path: base
  destination:
    server: https://kubernetes.default.svc
    namespace: openshift-devspaces
  syncPolicy:
    automated:
      selfHeal: true
EOF
----

== Exercise 5: Add some guardrails to developer workspaces

OK, so we have Dev Spaces installed and have successfully deployed a workspace.  In this next exercise we will add some guardrails to our Dev Spaces configuration that will set some resource limits on developers so that they cannot consume too many resources and cause disruption to other users or waste compute resources.

We are going to configure the following:
+
* Resource Caps for Dev Spaces workspaces - Configured in the CheCluster.  This setting will silently replace resource requests or limits that exceed the specified caps
* Resource Defaults for Dev Spaces workspaces - Configured in the CheCluster.  This setting will inject default values into workspaces that do not specify the values in the devfile.yaml
* ResourceQuotas - An OpenShift resource that sets total limits on resource consumption in a user's dev spaces namespace
* LimitRanges - An OpenShift resource that sets container level constraints on resource consumption
* Stale Workspace Pruner - Configured in a DevWorkspaceOperatorConfig resource.  This setting will delete workspaces that have not been started in a configurable amount of time

These new resources are defined in https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/ocp-pe-wkshp-dev-spaces-config.git[rhdh/ocp-pe-wkshp-dev-spaces-config,window=gitlab].

Click on that link above and navigate to `overlays/02-guardrails`
+
* quotas.yaml - Contains an OpenShift Template which defines ResourceQuotas and LimitRanges.  The Dev Spaces operator will use the Template to create the resources in each user's dev spaces namespace that is managed by the operator.
* workspace-pruner.yaml - Defines a DevWorkspaceOperatorConfig which configures the built in workspace pruner.  The time is set for 30 days.
* patches/checluster.yaml - Contains a patch for the CheCluster resource which will set the resource caps and defaults.

Now, apply the changes to the Dev Spaces configuration:

. In the **Terminal** tab, patch the Argo CD Application:
+
[source,bash,role="execute",subs="attributes+"]
----
oc patch application openshift-dev-spaces -n openshift-gitops --type merge -p '{"spec":{"source":{"path":"overlays/02-guardrails"}}}'
----
